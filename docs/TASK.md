# 139. RAG-система / дообучение LLM под домен

**Руководители:** Мовсумов Денис, Абакумов Юрий, Цуриков Виталий, Панчук Георгий, Мустафин Фарид, Александр Голубев, Родионов Никита

- **Тип задачи:** question answering, генерация текста
- **Данные:** собственный корпус документов или открытые корпуса (например, статьи arXiv)
- **Методы:** эмбеддинги + vector store (FAISS/Qdrant/Chroma) + retrieval + генерация LLM; альтернатива — LoRA fine-tuning небольшой open-source модели
- **Метрики:** качество ответов (human eval, RAGAS-метрики: faithfulness, relevance), latency
- **Усложнения:** сравнение чистого RAG vs fine-tuning; борьба с hallucinations; тест на adversarial-вопросах
- **Уровень:** PRO

**Проблема:** пользователям нужны точные ответы по большому корпусу документов, а обычный поиск по ключевым словам не даёт связного ответа, а LLM без контекста — "галлюцинирует".

**Что сделать?:** построить систему вопрос-ответ по корпусу документов на основе RAG (или дообученной LLM).

## Возможные задачи:

- сбор и подготовка корпуса документов
- построение эмбеддингов и векторного индекса
- реализация retrieval + генерации ответа
- формирование тестового набора вопросов с эталонами
- оценка качества ответов (human eval/RAGAS)
- анализ и минимизация случаев галлюцинаций

**Критерии приемки:** собран и проиндексирован корпус документов; на тестовом наборе вопросов ответы оценены по релевантности/достоверности (human eval или RAGAS-метрики) выше согласованного порога; задокументированы случаи неудачных ответов и предложены меры их снижения.
